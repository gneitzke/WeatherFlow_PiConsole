## Findings

Read-only audit; no files changed. The server in this checkout is `design/almanac/kiosk/serve.py`.

### F1. Fresh JSON can conceal dead observations — severity: high

- **Where:** [lib/almanac_emit.py:1093](lib/almanac_emit.py:1093), lines 1108 and 676; [serve.py:56](design/almanac/kiosk/serve.py:56); [console_live.html:2091](design/almanac/console_live.html:2091).
- **Defect:** Freshness measures emission or download time, without checking observation age. Lightning age is copied from the last parser calculation.
- **Failure scenario:** An observation at time T remains cached while emission continues at T+3600. The reproduced payload still reports 72°F, `lightningSinceSec: 0`, and `lightningActive: true`, with a fresh `ts`. `/health` considers it healthy. Likewise, downloading a September 1 WAQI observation on September 6 produces `aqiStale: false`.
- **Fix direction:** Preserve observation timestamps separately from engine heartbeat and fetch timestamps. Derive lightning age from its event epoch; expose source freshness per device/provider. Distinguish an offline sensor from a stalled engine.
- **Confidence:** confirmed.

### F2. Formatted NaN and infinity can stop the entire JSON feed — severity: high

- **Where:** [lib/almanac_emit.py:181](lib/almanac_emit.py:181), lines 196, 989 and 1040.
- **Defect:** `_num` rejects floating-point NaN but accepts `"nan"`, `"inf"`, and floating-point infinity. The barograph also accepts infinity.
- **Failure scenario:** The core formatter converts NaN temperature to `['nan', '℃']`. `_build_payload()` then contains `temp: nan`; serialization with `allow_nan=False` raises `ValueError`. One bad field prevents every field from updating.
- **Fix direction:** Apply finite-number validation after every numeric conversion, including series values. Preserve strict JSON serialization and map invalid measurements to null. Test the actual formatter → emitter → serializer path.
- **Confidence:** confirmed.

### F3. Hung polls never mark the display stale, and request counts do not prove rendering — severity: high

- **Where:** [console_live.html:2091](design/almanac/console_live.html:2091), lines 2238–2263; [serve.py:37](design/almanac/kiosk/serve.py:37).
- **Defect:** Polls have no deadline or overlap guard. Staleness is checked only after rendering or settled failures. `failCount` resets before rendering succeeds, and the server counts requests before knowing whether they succeeded.
- **Failure scenario:** A harness accumulated 101 unsettled fetch promises with no stale indication. Repeated JSON `null` responses followed by render errors left `failCount` at 1 forever. Requests returning errors—or requests from another client—still contribute to the kiosk’s supposed render heartbeat.
- **Fix direction:** Use one bounded request at a time, an independent freshness timer, payload validation, and success bookkeeping after rendering. Distinguish requests received from successful local rendering.
- **Confidence:** confirmed.

### F4. Short REST responses can abort complete observation updates — severity: medium

- **Where:** [lib/derived_variables.py:1244](lib/derived_variables.py:1244), lines 923 and 1361–1364; [lib/observation_parser.py:116](lib/observation_parser.py:116), lines 197 and 507.
- **Defect:** Response acceptance does not establish array lengths or row shapes before indexing. Yesterday’s statistics assume two daily rows; yearly rain checks `stats_month` before indexing `stats_year`. Websocket observation rows are also indexed without shape validation.
- **Failure scenario:** A successful statistics response containing only today’s row passes validation, then raises `IndexError` at `stats_day[-2]`. Running the complete Tempest parser reproduced the exception and left the displayed temperature at its startup placeholder.
- **Fix direction:** Validate packet/row shapes before extraction. Select statistics by calendar date, handle absent history as unavailable, and allow unrelated current measurements to publish.
- **Confidence:** confirmed.

### F5. Dropped duplicates still erase the REST cache — severity: medium

- **Where:** [lib/observation_parser.py:127](lib/observation_parser.py:127), lines 221, 289 and 359; [lib/almanac_emit.py:1017](lib/almanac_emit.py:1017).
- **Defect:** All four guards run after the per-device API dictionary is replaced.
- **Failure scenario:** A REST-enabled Tempest observation populates `24Hrs`, `today`, and other cache entries. Its echo is correctly excluded from integration but leaves only `{'flagAPI': 0}`. Once the emitter’s existing series cache expires, the barograph receives `[]`.
- **Fix direction:** Reject duplicates before any state mutation. Add REST-enabled cache-preservation assertions for all four message types.
- **Confidence:** confirmed.

### F6. Statistics-mode retries can repeatedly fetch the wrong endpoint — severity: medium

- **Where:** [lib/observation_parser.py:163](lib/observation_parser.py:163), lines 178–183; [lib/derived_variables.py:908](lib/derived_variables.py:908).
- **Defect:** Missing daily strikes trigger `today`, but statistics mode derives that value exclusively from `statistics`. Fetching statistics is gated only by missing month/year values.
- **Failure scenario:** Monthly/yearly totals are initialized, but today’s strike count is null. An eligible retry calls `last_24h` and `today`, never `statistics`; today’s count remains null. Missing yesterday rain has the analogous endpoint mismatch.
- **Fix direction:** Determine required endpoints from both missing values and the selected backend. Test partial initialization with statistics mode enabled, beyond testing the retry clock alone.
- **Confidence:** confirmed.

### F7. Solar-event handling uses host-local timestamps and can abort polar-station updates — severity: medium

- **Where:** [lib/derived_variables.py:1686](lib/derived_variables.py:1686), lines 1692–1693 and 1737–1743; [lib/observation_parser.py:501](lib/observation_parser.py:501).
- **Defect:** PyEphem’s UTC datetimes are passed to naive `.timestamp()`. Rise/set exceptions are unhandled, and daylight-factor division is unguarded. PyEphem documents its dates as UTC. [PyEphem reference](https://rhodesmill.org/pyephem/quick.html)
- **Failure scenario:** With host TZ `Europe/London`, the reproduced July sunrise timestamp was 3,600 seconds early. At Tromsø on June 21, `peak_sun_hours()` raised `AlwaysUpError`, aborting the parser before publication.
- **Fix direction:** Use explicitly UTC event timestamps and events belonging to the intended station day. Handle polar day/night and zero daylight fractions while continuing radiation integration.
- **Confidence:** confirmed.

### F8. Yearly rainfall briefly doubles its accumulated baseline at midnight — severity: medium

- **Where:** [lib/derived_variables.py:1393](lib/derived_variables.py:1393).
- **Defect:** The displayed yearly total adds `year[2]` twice instead of adding yesterday’s daily accumulation.
- **Failure scenario:** Before midnight: yearly baseline 100 mm, yesterday 5 mm, displayed year 105 mm. First observation after midnight with zero new rain displays **200 mm**, while its internal baseline correctly becomes 105 mm. The next observation corrects the display.
- **Fix direction:** Calculate displayed and retained totals from the same explicit period components. Add a station-midnight regression with unequal yearly and daily totals.
- **Confidence:** confirmed.

### F9. Lightning frequency excludes quiet minutes and can include out-of-window strikes — severity: medium

- **Where:** [lib/derived_variables.py:800](lib/derived_variables.py:800), lines 804, 816–818, 831–849; [lib/almanac_emit.py:1231](lib/almanac_emit.py:1231).
- **Defect:** The average uses only positive-count samples. Separately, an index computed from filtered timestamps is applied to the unfiltered observation array.
- **Failure scenario:** Ten strikes one minute ago, with every other minute quiet, produces **10/min** instead of 1/min over ten minutes. Earlier null records can also shift the slice backward into older strike activity.
- **Fix direction:** Filter timestamp/count pairs together, use explicit window boundaries, and calculate a rate over elapsed coverage including quiet minutes.
- **Confidence:** confirmed.

### F10. Forecast retries and emitter lifecycle accumulate scheduled work — severity: medium

- **Where:** [lib/almanac_emit.py:321](lib/almanac_emit.py:321), lines 342–358 and 430–438.
- **Defect:** Each hourly failure starts another independent two-minute retry chain. Repeated `start()` calls retain previous provider schedules; `stop()` misses forecast schedules and one-shot callbacks.
- **Failure scenario:** Simulating 24 hours of immediate network failures through the real fetch method produced **9,024 attempts and 25 pending retry chains**. A separate `start(); start(); stop()` harness left 13 scheduled handles uncancelled.
- **Fix direction:** Track every scheduled handle, permit one retry chain/in-flight fetch per provider, and fence callbacks belonging to stopped instances.
- **Confidence:** confirmed.

### F11. Off-thread AQI updates publish inconsistent combinations of fields — severity: medium

- **Where:** [lib/almanac_emit.py:673](lib/almanac_emit.py:673), lines 694–701 and 1196–1205.
- **Defect:** Current AQI, category, timestamp, and forecast are assigned separately. The emit tick can observe a partially updated result.
- **Failure scenario:** Pausing the worker during forecast summarization produced `aqi: 20`, old `aqiPeak: 160`, old `aqiTrend: "rising"`, and `aqiStale: false`. On worker completion, the peak became 20 and the trend steady.
- **Fix direction:** Construct and validate an immutable provider result locally, then publish it as one snapshot. Read each snapshot once per emit tick.
- **Confidence:** confirmed.

### F12. Cached alerts remain active after their expiry — severity: medium

- **Where:** [lib/almanac_emit.py:935](lib/almanac_emit.py:935), lines 959–967 and 1208–1210; [console_live.html:2152](design/almanac/console_live.html:2152).
- **Defect:** Expiration is checked only during downloads. Subsequent emits reuse the already-collapsed list.
- **Failure scenario:** An alert fetched at 12:00 expires at 12:01. At 12:02 it still appears active with `alertsStale: false`; normally it can remain until the 12:15 refresh, longer during an outage.
- **Fix direction:** Retain individual alert lifetimes, expire and regroup them at emission time, then recalculate the count. Simply filtering collapsed groups would incorrectly discard later-expiring members.
- **Confidence:** confirmed.

### F13. An unresponsive HTTP child can defeat the watchdog — severity: medium

- **Where:** [almanac-kiosk.sh:179](design/almanac/kiosk/almanac-kiosk.sh:179), lines 208 and 222–237.
- **Defect:** `read_polls` has no timeout. The bounded health check treats an empty/unparseable response as success by resetting `stale_hits`. Server recovery otherwise checks only PID existence.
- **Failure scenario:** The server remains alive but stops responding. Four-second health requests return no status and reset failure tracking. The next render check can block forever inside `read_polls`, preventing all subsequent process supervision.
- **Fix direction:** Bound every watchdog request, count transport/parse failures explicitly, and recover the failed server separately from the engine.
- **Confidence:** confirmed.

### F14. TERM cleanup returns to the relaunch loop instead of stopping — severity: medium

- **Where:** [almanac-kiosk.sh:114](design/almanac/kiosk/almanac-kiosk.sh:114), lines 205–227; [almanac-kiosk.service:29](design/almanac/kiosk/almanac-kiosk.service:29).
- **Defect:** `trap cleanup EXIT INT TERM` performs cleanup on TERM but does not exit. Children can be relaunched during shutdown. Engine replacement also lacks confirmation that the previous process exited.
- **Failure scenario:** The reproduced Bash trap executes cleanup, continues after TERM, then executes cleanup again on eventual exit. During service shutdown, the launcher can survive until the 15-second forced-stop deadline. Systemd’s default final action is SIGKILL. [Systemd kill settings](https://raw.githubusercontent.com/systemd/systemd/main/man/systemd.kill.xml)
- **Fix direction:** Make TERM/INT initiate exit; perform final cleanup through EXIT. Track current children, wait/reap them, and enforce bounded escalation before replacement.
- **Confidence:** confirmed.

### F15. Cold-boot auto-detection can permanently choose the wrong display backend — severity: medium

- **Where:** [almanac-kiosk.sh:55](design/almanac/kiosk/almanac-kiosk.sh:55), lines 88–94 and 162; [almanac-kiosk.service:19](design/almanac/kiosk/almanac-kiosk.service:19).
- **Defect:** Backend selection occurs once, before readiness waiting. “Wayland not ready yet” becomes “use X11.”
- **Failure scenario:** A lingering user service starts before labwc creates its socket. The launcher selects X11. Labwc subsequently becomes ready, but every Chromium launch still uses X11 on `:0`; a Wayland-only session never recovers.
- **Fix direction:** Detect and wait for the backend together, respecting explicit overrides. If readiness times out, fail cleanly instead of launching against an unverified display.
- **Confidence:** confirmed.

### F16. Forecast summaries assume adjacent array entries are adjacent calendar days — severity: medium

- **Where:** [lib/almanac_emit.py:461](lib/almanac_emit.py:461), lines 493–498 and 760–770.
- **Defect:** The existing tomorrow hint assumes row 1 is tomorrow after incomplete rows have been dropped. WAQI similarly assumes its first two dated rows mean today and tomorrow.
- **Failure scenario:** September 7 lacks a high temperature, so shaping retains September 6 and September 8. A storm on September 8 becomes **“Thunderstorms tomorrow.”** A WAQI array beginning September 5 with peak 160 produces **“Unhealthy today”** on September 6 despite today’s peak being 40.
- **Fix direction:** Select forecast entries by explicit dates in the appropriate timezone. Test missing days, historical prefixes, and midnight transitions.
- **Confidence:** confirmed.

### F17. AQI markers disagree with their color bands — severity: medium

- **Where:** [lib/almanac_emit.py:675](lib/almanac_emit.py:675), lines 696 and 1198.
- **Defect:** WAQI’s individual PM2.5 AQI is assigned to the same field used for Open-Meteo PM2.5 concentration. WAQI documents individual pollutant AQIs separately from raw concentrations. [WAQI API documentation](https://aqicn.org/api/)

### F24. Alert transitions retain callbacks after their state ends — severity: low

# Adversarial re-review of the fixes (before 3c0f75e)

All four must-fix items and all four should-fix items below were applied before the commit.

## Verdict

**DO NOT SHIP** — the diff introduces stale-data reuse and breaks watchdog recovery in both kiosk and headless modes. All 175 tests passed; they miss these regressions.

## Must fix before deploy

1. **Persistent REST seeds can silently restore obsolete totals.**  
   [lib/observation_parser.py:146](lib/observation_parser.py:146), also lines 246, 320 and 395.  
   **Failing input:** retain yesterday’s `today` response, receive a missing radiation reading, then a valid reading while `_seed_due()` is false. `peak_sun_hours()` consumes yesterday’s cached radiation and stamps the result as current. I reproduced a stale **0.6-hour** total. Once populated, it stops requesting a fresh seed. Other seed consumers are exposed similarly.  
   **Exact fix:** restore `self.api_data[device_id] = {'flagAPI': self.flag_api[i]}` at all four locations, **keeping the duplicate guard above it**. This preserves duplicate-message cache protection without changing seed lifetime for accepted messages.

2. **The watchdog discards the response that identifies a stuck engine.**  
   [design/almanac/kiosk/almanac-kiosk.sh:217](design/almanac/kiosk/almanac-kiosk.sh:217).  
   **Failing input:** the engine remains alive but stops updating `wx.json`. `serve.py` correctly returns HTTP **503** with `{"status":"stale", ...}`. `curl -f` suppresses that body and fails; line 268 clears `health`. Consequently, the watchdog repeatedly restarts the server instead of the engine.  
   **Exact fix:** change `curl -fsS` to `curl -sS`, retaining both timeouts. Parse the body and accept only `ok`, `stale`, or `error`; treat other responses as health failures.

3. **Headless mode never defines `health_response`.**  
   [design/almanac/kiosk/almanac-kiosk.sh:216](design/almanac/kiosk/almanac-kiosk.sh:216).  
   **Failing input:** `WFP_MODE=headless`. The function definition is inside the kiosk-only branch beginning at line 193, but the common watchdog calls it at line 268. After warmup, every two checks restart a healthy server. I confirmed the function is undefined when evaluating that branch in headless mode.  
   **Exact fix:** move `health_response()` outside and above the kiosk-only branch.

4. **F10: retry registration races with `stop()`.**  
   [lib/almanac_emit.py:473](lib/almanac_emit.py:473), together with lines 415–447.  
   **Failing interleaving:** the forecast worker passes `_running`, then `stop()` cancels and clears the registry, then the worker registers its retry. My deterministic interleaving left **one live Clock handle and one retry entry after stop**. The current tests execute workers inline and miss this.
